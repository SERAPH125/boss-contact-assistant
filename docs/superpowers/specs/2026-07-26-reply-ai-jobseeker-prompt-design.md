# 求职者 AI 回复提示词部署设计

日期：2026-07-26

## 目标

仅调整 `ReplyAI` 的分类与草稿系统提示词，使模型遵循用户给定的求职者身份、45 个汉字以内、拒绝语义处理、事实依据和敏感承诺限制。

## 范围

- 在分类提示词中加入六条最高优先级规则。
- 在草稿提示词中加入同一组规则，并把建议回复长度从约 80 个汉字收紧为不超过 45 个汉字。
- 保留现有分类枚举、严格 JSON 输出协议、证据校验、确定性策略、会话状态机和发送流程。
- 更新 `ReplyAI` 契约测试，验证两类系统提示均包含这些规则且草稿提示包含 45 字限制。
- 更新 AI 托管开发文档，说明本次仅调整模型提示，不构成确定性拒绝拦截。

## 明确不做

- 不新增 `rejected`、`conversation_closed` 或 `no_reply` 分类。
- 不新增“已结束－未匹配”状态。
- 不修改硬风险正则、自动回复类别或自动发送门禁。
- 不新增侧栏自定义系统提示词输入框。
- 不保证模型一定按提示词识别“不合适”；模型输出仍会经过现有分类与策略流程。

## 提示词语义

模型被告知：

1. 身份是求职者本人，回复简短、自然、礼貌，不超过 45 个汉字。
2. 明确拒绝时不继续争取、不追问、不生成自动回复，并视为“已结束－未匹配”。
3. 含糊拒绝时只建议草稿并等待人工确认。
4. 只有可由简历或 HR 常用问答直接支持的低风险事实问题才适合自动回复。
5. 不编造事实，不承诺薪资、面试或到岗时间。
6. 用户选择礼貌结束时，仅使用一次固定礼貌回复。
7. 会话结束后不得重复回复。

由于本次不修改输出协议和状态机，第 2、3、6、7 条只作为模型行为指引；最终是否自动发送仍由现有确定性策略决定。

## 测试与验收

- 先新增失败测试，证明当前系统提示词不包含完整规则和 45 字限制。
- 修改生产提示词后运行 `tests/reply-ai.test.js`。
- 运行项目完整测试，确认现有分类解析、证据校验和托管流程没有回归。
- 检查最终差异只涉及提示词、对应测试和开发文档。
