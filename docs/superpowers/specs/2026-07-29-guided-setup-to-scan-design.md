# 配置引导至岗位扫描设计

日期：2026-07-29

## 问题

当前首次配置路径为“平台 → API → 求职设置 → 直接扫描”，AI 托管是独立页。用户容易在未配置回复依据、飞书通知和托管规则时先完成扫描与联系，之后才发现自动托管不能运行。

## 已确认方案

采用“BOSS 完整引导、允许跳过；智联保持直接扫描”的流程：

1. 平台 → API；
2. API → 求职设置；
3. BOSS 求职设置：
   - 主操作“保存并下一步：AI 托管”；
   - 次操作“跳过 AI 托管，直接扫描 Boss 岗位”；
4. BOSS AI 托管：
   - 保留“保存托管设置”；
   - 新增主操作“保存全部配置并扫描 Boss 岗位”；
   - 只有托管设置保存成功后才复用现有岗位扫描入口；
5. 智联求职设置继续使用“保存并扫描智联岗位”，不进入不支持的 AI 托管步骤。

## 行为约束

- 从求职设置前往 AI 托管前，先保存 API/简历要点和当前平台求职设置。
- BOSS 最终扫描按钮必须复用现有扫描函数，不能复制扫描协议。
- 托管前置条件失败时不得扫描，并复用现有缺项定位。
- “跳过 AI 托管”是明确次级操作，仍允许只使用扫描和人工联系。
- 智联不展示前往 AI 托管的引导按钮。
- 日常用户仍可直接点击任一配置子页，不强制重走向导。
- 不新增扩展权限、网络接口或外部依赖。

## 测试

- 契约测试固定三个新增/调整入口及用户可见文案。
- 运行时测试验证 BOSS 求职设置保存后跳转 AI 托管。
- 运行时测试验证最终入口只有在托管保存成功后才触发扫描。
- 运行时测试验证托管保存失败不触发扫描。
- 运行时测试验证智联隐藏 AI 托管引导并保留直接扫描。

## 开源参考

- [Automa](https://github.com/AutomaApp/automa)：先完成工作流组成，再执行自动化，同时允许用户直接控制执行入口。
- [Activepieces](https://github.com/activepieces/activepieces)：连接配置、必填校验与 Human-in-the-loop 是自动化运行前的显式组成部分。
- [n8n credentials setup](https://github.com/n8n-io/n8n-docs/blob/main/docs/integrations/builtin/credentials/google/oauth-single-service.md)：以明确前置步骤引导用户完成凭据配置后再进入后续使用。
