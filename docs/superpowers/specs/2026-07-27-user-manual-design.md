# 求职联系助手用户操作手册设计

**日期：** 2026-07-27  
**状态：** 待用户确认  
**目标文件：** `docs/user-manual.md`

## 1. 目标

为没有开发背景的普通求职用户提供一份可独立完成操作的中文 Markdown 手册。用户应能仅依靠该手册完成：

1. 在 Chrome 或 Edge 中安装扩展；
2. 配置平台、AI 服务、求职条件和简历依据；
3. 扫描、筛选并联系岗位；
4. 正确启用和管理 BOSS AI 对话托管；
5. 配置飞书通知并处理待确认消息；
6. 理解常见状态、能力边界和恢复方法。

## 2. 交付范围

- 新增 `docs/user-manual.md`。
- 在 `README.md` 顶部增加清晰的用户手册入口。
- 不修改扩展功能、交互或运行逻辑。
- 首版采用文字、步骤、表格和提示块，不嵌入容易随 UI 变化失效的截图。

## 3. 内容组织方案

采用“快速上手 + 功能查阅 + 故障排查”的分层结构。

### 3.1 第一层：新用户快速上手

按照真实操作顺序编排：

1. 安装扩展；
2. 打开招聘网站并登录；
3. 选择平台；
4. 配置并测试 API；
5. 填写求职设置；
6. 扫描岗位；
7. 在“岗位筛选”中勾选；
8. 确认联系计划；
9. 在“执行”中查看结果。

该层只保留完成首次闭环所需的信息，不提前展开内部状态机。

### 3.2 第二层：功能详细说明

按用户任务而不是代码模块组织：

- 平台支持情况；
- API 配置和本地保存；
- 求职意向、简历材料、平台筛选和联系节奏；
- 岗位扫描、筛选、确认和执行；
- BOSS AI 托管前置条件；
- 登记岗位、逐岗位托管、一键托管和手动结束；
- 检查间隔、随机回复延迟、静默时段和普通回复额度；
- 自动回复、待确认和明确拒绝结束语的分流；
- 飞书 Webhook、签名密钥、测试、保存与遮罩显示；
- 待确认任务的修改、发送、不回复、清除和关闭托管；
- 真实外发演练的用途及其不能证明的能力。

### 3.3 第三层：状态和故障排查

提供两张用户可查表：

1. 托管状态 → 含义 → 用户下一步；
2. 常见症状 → 判断依据 → 恢复步骤。

至少覆盖：

- “检查 0 个”；
- 登记成功但列表未增加；
- 会话暂不可用；
- 等待 HR；
- 等待确认；
- 正在核验发送；
- 已暂停；
- 已结束－未匹配；
- Webhook 输入框重开后为空；
- Chrome 与 Edge 配置不共享；
- 登录失效、验证码、页面结构变化和发送结果未知。

## 4. 写作规则

- 使用界面中现有中文标签，如“岗位筛选”“联系已选”“保存托管设置”。
- 每个操作步骤都说明“在哪里、点击什么、成功标志是什么”。
- 首次出现专业词时用普通语言解释，不要求用户理解 MV3、Service Worker、canonical ID 等开发术语。
- 对高风险动作明确标注是否会真实发送消息。
- 不把“按钮已点击”描述为“操作成功”；成功判断使用持久列表、状态提示或招聘网站中的实际消息证据。
- 不展示 API Key、Webhook、签名密钥或真实聊天内容。
- 不宣称浏览器关闭后仍能监控。
- 不承诺所有招聘网站、DOM 版本或风控场景都已真实验证。

## 5. 准确性来源

手册以以下顺序确定事实：

1. 当前 `src/sidepanel.html` 中的可见界面和按钮；
2. 当前 `README.md`、`docs/07-multi-platform-design.md` 和 `docs/08-boss-ai-trusteeship.md`；
3. 与用户可见行为有关的自动化测试；
4. 已记录的真实平台验证证据。

开源资料只用于借鉴文档结构，不覆盖本项目的真实行为：

- `huluobo2237-pixel/JobCopilot`：安装、平台、配置和风险说明的组织方式；
- `can4hou6joeng4/boss-agent-cli`：快速开始、能力边界和诊断排障的分层方式；
- `GoogleChrome/chrome-extensions-samples`：浏览器扩展安装和使用术语。

本地知识库《浏览器扩展 AI 会话托管可靠性复盘》的既有结论用于构建“症状—判断—恢复”排障表；手册的信息架构和面向普通用户的表达方式属于本任务新增设计。

## 6. 关键行为说明

手册必须明确以下容易误解的行为：

- 飞书配置不是输入即自动保存；需点击“保存托管设置”。
- Webhook 和签名密钥保存后不会回填原文，只显示“已保存；重新输入可替换”。
- API Key、Webhook 和签名密钥只保存在当前浏览器扩展的本地存储中，不是系统钥匙串。
- Chrome 与 Edge、不同浏览器 Profile 之间默认不共享配置。
- AI 托管目前仅适用于 BOSS 已登记会话。
- 监控要求浏览器保持运行、BOSS 登录有效且全局及逐岗位托管均已开启。
- 普通安全回答可能延迟 30–300 秒；周期检查默认 10 分钟，可选 5/10/15 分钟。
- 薪资、面试、到岗、联系方式、经历补充、测评、Offer、承诺、附件和未知消息进入人工确认。
- AI 严格判定明确拒绝后只发送一次礼貌结束语并结束会话；结束会话不会被一键托管重新开启。
- 真实外发演练验证的是合成消息决策与发送链，不等同于证明真实 HR 新消息已被定时捕获。
- 卸载扩展会清除 `chrome.storage.local` 中的本地配置和状态。

## 7. 验证标准

正式手册完成后执行：

1. 对照 `src/sidepanel.html` 检查所有按钮和标签名称；
2. 对照当前代码检查默认值、可选值和状态行为；
3. 搜索并消除“审核”等已废弃 UI 名称；
4. 搜索 `TBD`、`TODO`、占位符和真实凭证格式；
5. 检查 Markdown 标题、目录、站内链接和表格；
6. 确认 README 的手册链接有效；
7. 运行与界面契约有关的现有测试，确保纯文档更新没有伴随意外代码变化；
8. 使用 `git diff --check` 检查格式。
