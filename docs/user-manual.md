# 求职联系助手用户操作手册

适用版本：0.3.6  
更新日期：2026-07-28

“求职联系助手”是一个运行在 Chrome 或 Edge 侧边栏中的半自动求职扩展。它帮助你完成：

1. 按求职意向扫描岗位；
2. 由你筛选并勾选要联系的岗位；
3. 在最终确认后，逐个发起沟通；
4. 在 BOSS 直聘中登记已经建立联系的会话；
5. 低频检查 HR 新消息，并按安全规则自动回复或交给你确认。

> 重要：扩展不会替你保证求职结果，也无法保证招聘网站长期保持相同页面结构。自动化操作可能触发平台限制或账号风险。请只在你本人有权使用的账号中操作，并从小批量开始验证。

## 1. 使用前先了解

### 1.1 当前支持范围

| 功能 | BOSS 直聘 | 智联招聘 |
| --- | --- | --- |
| 扫描岗位 | 支持 | 支持 |
| 人工筛选岗位 | 支持 | 支持 |
| 联系已选岗位 | 支持 | 支持 |
| AI 对话托管 | 支持 | 暂不支持 |

同一时间只能运行一个招聘平台。切换平台会切换到该平台独立保存的求职设置，并清空当前岗位勾选。

### 1.2 核心工作流

完整流程是：

对于 BOSS，推荐流程是：

`配置平台 → 测试 API → 填写求职设置 → 配置 AI 托管 → 扫描 → 岗位筛选 → 确认联系 → 查看执行`

AI 托管仍可跳过；智联不支持 AI 托管，因此从“求职设置”直接进入扫描。

扩展默认不会因为扫描到岗位就直接联系。只有你在“岗位筛选”中勾选岗位，并在确认单中点击“确认联系”，才会开始操作招聘网站。

### 1.3 运行条件

使用期间请确保：

- Chrome 或 Edge 保持运行；
- 对应招聘网站已经登录；
- 招聘网站没有停留在验证码、登录失效或异常限制页面；
- 需要发送消息时，BOSS 聊天页处于当前窗口中可见、已加载且为活动标签页；
- 电脑没有进入会让浏览器完全休眠的状态。

关闭浏览器后，扩展不能继续监控或回复消息。

## 2. 安装与打开扩展

### 2.1 在 Chrome 中安装

1. 打开 `chrome://extensions`。
2. 打开右上角“开发者模式”。
3. 点击“加载已解压的扩展程序”。
4. 选择本项目根目录。
5. 确认扩展列表中出现“求职联系助手”。
6. 打开 BOSS 直聘或智联招聘并完成登录。
7. 点击浏览器工具栏中的扩展图标，打开“求职联系助手”侧边栏。

### 2.2 在 Edge 中安装

1. 打开 `edge://extensions`。
2. 打开“开发人员模式”。
3. 点击“加载解压缩的扩展”。
4. 选择本项目根目录。
5. 登录招聘网站并打开扩展侧边栏。

Chrome 与 Edge 使用各自独立的浏览器资料。API Key、飞书 Webhook、托管记录等本地数据不会在两个浏览器之间自动同步。

### 2.3 更新代码后的重载

如果扩展代码已经更新：

1. 打开浏览器扩展管理页；
2. 找到“求职联系助手”；
3. 点击卡片上的“重新加载”；
4. 回到招聘网站并重新打开侧边栏。

只刷新招聘网站页面不等于重载扩展代码。

## 3. 新用户快速上手

本章用于第一次跑通“扫描、筛选、联系”主流程。更短的独立版本见 [新用户快速上手](quick-start.md)。

### 第 1 步：选择平台

进入“配置 → 平台”，选择 BOSS 或智联。

- BOSS：支持岗位扫描、联系及 AI 对话托管；
- 智联：支持扫描与联系。

### 第 2 步：配置 AI 服务

进入“配置 → API”：

1. 选择服务商；
2. 填写你自己的 API Key；
3. 如果使用 OpenAI 兼容服务，填写 Base URL；
4. 点击“测试连接”；
5. 看到测试成功后，点击“保存 API 配置”。

API Key 只保存在当前浏览器的本地扩展存储中。修改 API Key、服务商或 Base URL 后，应重新测试连接。

没有 API Key 时，部分岗位筛选可退化为规则判断，但 AI 对话托管不能正常启用。

### 第 3 步：填写求职设置

进入“配置 → 求职设置”，至少填写：

- 目标岗位或关键词；
- 城市；
- 简历要点；
- 招呼语；
- 扫描数量与每日上限。

建议简历要点按行填写，只写真实事实，例如：

```text
目标岗位：跨境电商运营
目前城市：杭州
有 TikTok 店铺运营经历
熟悉数据分析和内容优化
暂无亚马逊独立运营经验
```

不要把希望 AI 猜测的内容写成模糊指令。托管回复只应引用简历要点或已填写问答中的事实。

### 第 4 步：扫描岗位

根据当前平台选择入口：

- BOSS 推荐点击“保存并下一步：AI 托管”，完成飞书、回复依据和托管规则后，点击“保存全部配置并扫描 Boss 岗位”；
- 如果暂时只想扫描 BOSS 岗位，可点击次级操作“跳过 AI 托管，直接扫描 Boss 岗位”；
- 智联点击“保存并扫描智联岗位”，不会进入不支持的 AI 托管步骤。

扫描只读取和整理岗位，不会自动联系。完成后，底部切换到“岗位筛选”。

### 第 5 步：筛选岗位

在“岗位筛选”中：

1. 点击职位名可打开招聘网站中的岗位详情；
2. 点击职位卡其他区域可勾选或取消；
3. 可使用“全选高分”快速选择推荐岗位；
4. 核对公司、岗位、薪资、城市和推荐理由；
5. 选择“联系已选”，或在 BOSS 中选择“联系已选并开启 AI 托管”。

默认不选择任何岗位。不要只看 AI 分数，最终决定由你完成。

### 第 6 步：确认联系计划

确认单会展示本次平台、岗位列表、今日额度、预计等待时间和简历状态。

- 点击“返回岗位筛选”、按 Escape 或点击遮罩：不会开始联系；
- 点击“确认联系”或“确认联系并开启 AI 托管”：按确认单中冻结的方式逐个处理本批岗位；
- 确认单有效期为两分钟，且只能使用一次。

### 第 7 步：查看执行结果

进入“执行”查看：

- 当前阶段；
- 已完成数量；
- 每个岗位的处理日志；
- 暂停、停止和安全停机原因。

遇到验证码、登录失效、次数上限、目标不确定或发送结果未知时，扩展会停止或要求人工检查。

### 第 8 步：确认 BOSS 会话已进入托管

如果选择“联系已选并开启 AI 托管”，BOSS 联系成功并取得可靠会话身份后，会自动登记并开启该会话。请到“配置 → AI 托管 → 已登记岗位”确认对应岗位已经出现且状态为“等待 HR”。

如果选择“联系已选”，BOSS 仍会尝试登记可靠会话，但不会自动开启；需要时可稍后在 AI 托管页手动开启。

如果扫描前选择了“跳过 AI 托管”，后续仍可随时进入 AI 托管页完成配置；详细前置条件、状态和验证方法见第 7 章。

## 4. 配置详解

### 4.1 平台

路径：“配置 → 平台”。

平台设置决定：

- 扫描哪个招聘网站；
- 使用哪套求职条件；
- 使用哪套招呼语和联系节奏；
- 今日联系计数归属哪个平台。

切换平台前，先确认当前执行任务已经结束。

### 4.2 API

路径：“配置 → API”。

#### 服务商

- DeepSeek：使用界面指定的模型和官方地址；
- OpenAI 兼容：适用于 OpenAI API 或兼容协议的模型服务。

#### API Key

填写你自己的密钥。该密钥用于岗位判断、HR 消息分类和回复生成。

#### Base URL

仅 OpenAI 兼容模式需要填写。公网地址应使用 HTTPS；本机服务可使用 `localhost` 或 `127.0.0.1`。

#### 测试与保存

推荐顺序：

1. 填写配置；
2. 点击“测试连接”；
3. 确认成功；
4. 点击“保存 API 配置”。

AI 托管会检查最近一次连接测试是否仍与当前配置一致。更换任何连接信息后，旧测试结果会失效。

### 4.3 求职意向

路径：“配置 → 求职设置 → 求职意向”。

#### 目标岗位 / 关键词

填写招聘网站中常见的岗位名称，例如“前端开发”“数据分析”“跨境电商运营”。

#### 城市

填写招聘平台支持的目标城市，例如“杭州”“金华”。扩展会读取 BOSS、智联各自的官方城市目录，将城市名称转换为平台代码，并在浏览器本地缓存七天。

如果官方目录暂时不可用，会优先使用仍有效的本地缓存和内置常用城市；如果最终仍无法确认城市代码，扫描会停止，不会把未知城市降级成全国搜索。

#### 包含词

用逗号分隔希望岗位包含的内容，例如：

```text
TikTok, 数据分析, 双休
```

设置包含词后，扩展不仅检查职位卡片的岗位名、公司和标签，还会以只读方式读取每个岗位的“职位描述”正文。只要任一包含词出现在上述字段中，即可通过这一层规则。

#### 排除词

用逗号分隔明确不接受的内容，例如：

```text
外包, 驻场, 纯销售
```

排除词同样会检查职位描述。职位详情读取失败时，扩展会明确显示“职位描述读取失败”，并停止把该岗位当作已经安全匹配，避免把“读取不到”误当成“没有命中”。

当 API Key 和简历要点均可用时，职位描述也会提供给 AI 作为岗位匹配依据；读取失败的岗位不会假装拥有完整职位信息。

### 4.4 简历材料

#### 简历要点

简历要点是 AI 回答 HR 问题的主要事实依据。建议包括：

- 当前城市和目标城市；
- 真实工作或项目经验；
- 工具、平台和语言能力；
- 经验年限；
- 可以公开给 HR 的求职状态；
- 明确没有的经验，防止 AI 误写。

#### 简历图片

简历图片是可选项。配置后，联系流程会在平台和页面条件允许时尝试发送。

发送前仍会校验当前会话身份。目标无法确认时，不会为了完成任务而向未知会话发送简历。

### 4.5 平台条件

#### BOSS

可过滤不活跃 BOSS，并选择活跃时间要求。推荐保持过滤开启。

#### 智联

可填写工作经验与学历。扫描完成后还会根据职位卡信息再次校验。

### 4.6 招呼语

招呼语在联系岗位时原样发送，可使用：

- `{jobName}`：岗位名；
- `{company}`：公司名。

示例：

```text
您好，我对{company}的{jobName}岗位很感兴趣，方便聊聊吗？
```

首条招呼不由 AI 临时生成。AI 托管只处理建联后的会话。

### 4.7 扫描与联系节奏

| 设置 | 含义 |
| --- | --- |
| 扫描数量 | 本轮最多读取多少岗位 |
| 每日上限 | 当前平台每天最多联系多少岗位 |
| 间隔最短/最长 | 两个岗位操作之间的等待范围 |
| 批次大小 | 连续处理多少个岗位后休息 |
| 批次休息最短/最长 | 每个批次之间的等待范围 |

建议第一次使用时只选择少量岗位，确认平台页面、招呼语和日志都符合预期后再扩大批次。

## 5. 扫描与岗位筛选

### 5.1 扫描不会发送消息

点击当前平台的扫描入口后，扩展会保存当前平台设置并读取岗位列表。BOSS 可从 AI 托管页的“保存全部配置并扫描 Boss 岗位”开始，也可从求职设置跳过托管直接扫描；智联使用“保存并扫描智联岗位”。扫描阶段不会发招呼、投递简历或修改托管会话。

BOSS 的职位卡共用右侧 SPA 详情面板。需要职位描述时，扩展会按当前可见批次逐个激活岗位，并在岗位稳定 ID 与目标一致后，只从同一个可见详情面板读取标题、标签、正文和招聘者身份；不会同时批量请求详情页，也不会把隐藏旧面板的正文拼到当前岗位。岗位较多时扫描会比只读卡片慢一些，这是为了防止把旧详情绑定到新岗位，也减少连续直连详情页进入“请稍候”软加载页的概率。

### 5.2 阅读岗位卡

岗位卡通常包含：

- 岗位名；
- 薪资；
- 匹配分数；
- 推荐或排除理由；
- 打开详情入口。

有 API Key 时，分数和理由可由 AI 结合简历判断；没有 API Key 时可能使用规则结果。

筛选结果分为三类：

- **建议**：岗位信息完整，规则和 AI 判断允许进入人工勾选；
- **待核对**：职位描述暂时读取失败或证据不完整，默认不选，但用户查看站点详情后可以手动勾选；
- **不匹配**：已经取得足够证据并确认不满足规则，不可勾选。

“职位描述读取失败”表示本次没有取得完整证据，不等同于岗位不匹配，也不能被 AI 当成推荐岗位。

### 5.3 勾选规则

- 初始状态默认全不选；
- “全选高分”只是一种快捷操作，仍需人工复核；
- “清空选择”会取消当前全部勾选；
- 切换平台会清空勾选；
- 只有已勾选岗位会进入联系确认单。

## 6. 确认并联系岗位

### 6.1 选择批量操作

- “联系已选”：BOSS 与智联都支持；只执行联系，不自动开启会话托管。
- “联系已选并开启 AI 托管”：仅 BOSS 支持；联系成功并可靠登记后，立即把新会话置为“等待 HR”。

两个入口互斥：点击任一个后，另一个会同时锁定，直到你取消确认或本次确认完成。扩展先生成一次性确认单，不会因为点击入口就立即在招聘网站执行。

“联系已选并开启 AI 托管”还会在生成确认单时检查 API 测试、回复依据、飞书测试、风险确认以及全局托管运行状态；不满足时确认单不会出现，岗位筛选页会直接显示失败原因与下一步。实际处理每个岗位开始时会检查一次，读取详情和拟人延时结束后、点击“立即沟通”前还会再次检查。任一条件失效时，本批次在下一次站点写入前停止，不会把普通“联系已选”偷偷升级为托管模式。

### 6.2 确认单

请核对：

- 当前平台是否正确；
- “后续处理”是仅联系，还是联系成功后开启 AI 托管；
- 岗位数量和岗位名单；
- 今日剩余额度；
- 招呼语和简历图片是否已配置；
- 预计等待时间是否可以接受。

确认后，后台仍会在每个岗位实际操作前逐项校验。

### 6.3 执行页

“执行”页提供：

- 当前阶段和进度；
- 逐项日志；
- “暂停”；
- “停止”；
- “重置会话”；
- 安全停机原因与建议操作。

任务运行时不要随意切换招聘平台或重置会话。

### 6.4 联系成功后的 BOSS 登记

BOSS 联系成功后，扩展会尝试把可靠的会话身份登记到“配置 → AI 托管 → 已登记岗位”：

- 使用“联系已选”时，只登记，不自动开启；
- 使用“联系已选并开启 AI 托管”时，可靠登记后自动开启；
- 每次点击“立即沟通”前，扩展都会重新激活目标职位，并锁定当前详情的稳定岗位 ID、标题、公司和 HR；按钮还必须属于这一个详情面板。即使拟人点击正在等待，只要期间岗位或 HR 发生切换，真正派发鼠标事件前也会停止；
- 如果职位详情本身读不到 HR，扩展会要求人工核对，不会用岗位卡片中的旧 HR 名称替代实际点击前的身份校验；
- BOSS 显示“已向BOSS发送消息”后，首条招呼已经由平台发出。扩展进入聊天页后不会再填写输入框或发送第二条招呼，而是只读核对当前页的 HR、公司和岗位，解析稳定会话身份并读取初始消息基线；
- 聊天页可见的 HR、公司和岗位必须全部匹配；同公司同岗位但 HR 不同会停止登记。BOSS 联系人接口可能只返回 HR 与公司，扩展只比较接口实际提供的可靠字段，并用已核验的页面岗位补全；接口中的“招聘专员 / 人事培训 / 人力资源专员”等 `title` 是招聘者职务，不会再误作岗位；
- 只有没有取得 BOSS 首次联系成功证据的兼容路径，才会在聊天页发送简历或招呼语。该路径发送前至少需要两个真正独立的身份字段；图片、文字和 Enter 动作前任一身份或页面作用域发生变化都会停止；
- “继续沟通”等按钮不会由通用弹窗清理自动点击。通用清理也不会点击含业务动作弹窗的 ×。即使“继续沟通”按钮稍后才出现，扩展也会按“已向BOSS发送消息”结果弹窗本身保护该回执，不会关闭弹窗或再次点击背后的“立即沟通”；按钮出现且可唯一确认后才进入聊天页并捕获会话身份。联系前若已有来源不明的结果弹窗或“继续沟通”弹窗，本次联系会直接停止。发送结果没有可靠证据时不会再次点击发送按钮；
- 如果鼠标按下后页面身份或弹窗状态才发生变化，扩展会把结果记为“可能已发生外部动作”，停止本批次并要求人工核对，不会自动重试；
- 登记或开启失败不会撤销已经发出的联系，执行日志会单独提示；
- 如果联系已经成功，但尚未取得规范会话 ID、聊天 URL 或初始消息指纹，扩展会明确记录“联系成功、托管未开启”，不会把它显示成托管成功；
- 已结束－未匹配的会话不会被批量操作重新开启。

判断是否登记成功，应同时满足：

1. “已登记岗位（N）”数量增加；
2. 列表中出现对应公司、岗位和 HR 的卡片。

页面上方一条“已登记”提示只能说明最近一次操作结果，不能替代岗位卡片。

## 7. BOSS AI 对话托管

### 7.1 托管能做什么

AI 托管会低频检查已经可靠登记并启用的 BOSS 会话：

- 识别登记之后新收到的 HR 消息；
- 对有明确事实依据的低风险问题生成回复；
- 在安全规则允许时延迟自动发送；
- 对重要或不确定问题创建“待确认”；
- 对明确拒绝发送一次礼貌结束语并结束托管；
- 对同一条消息去重，避免重复回复。

它不会扫描你账号中的所有聊天记录，只处理本地“已登记岗位”中的启用会话。

### 7.2 开启前置条件

开启全局 AI 托管前，需要：

1. 当前 API 配置已经测试成功；
2. “简历要点”或“HR 常用问答”至少提供一项有效回复依据；
3. 飞书通知已经启用、配置并测试成功；
4. 已接受界面中的平台风险提示；
5. BOSS 登录有效；
6. 至少有一个可靠登记的岗位会话。

缺少条件时，界面会提示具体缺项，不会真正创建监控任务。

### 7.3 全局设置

路径：“配置 → AI 托管”。

#### 先配置飞书通知

飞书通知配置现在位于 AI 托管页面最上方。首次使用时，请先完成：

1. 勾选“启用飞书待确认通知”；
2. 填写飞书 Webhook 和可选签名密钥；
3. 点击“发送飞书测试通知”；
4. 确认飞书群收到测试消息；
5. 再继续设置 AI 托管开关、检查间隔和回复规则。

飞书只负责通知，待确认消息仍需在插件中处理。更完整的机器人创建和敏感字段保存说明见第 8 章。

#### 开启 AI 对话托管

这是全局开关。打开并保存后，符合条件的单个岗位才可能被检查。

首次按完整引导配置时，可点击“保存全部配置并扫描 Boss 岗位”。扩展会先保存并校验托管设置，只有保存成功才进入已有岗位扫描流程；如果 API、回复依据、飞书测试或风险确认缺失，界面会定位到缺项且不会扫描。

#### 检查间隔

可选：

- 5 分钟；
- 10 分钟，默认值；
- 15 分钟。

这是低频轮询间隔，不代表 HR 发消息后会立刻回复。普通安全回复还会增加 30～300 秒的持久随机等待。

#### 每日自动回复上限

默认 10，允许设置 1～20。它限制普通自动回复数量。

明确拒绝后的单次礼貌结束不计入该额度。

#### 静默时段

开启后，静默期间只收集消息：

- 普通安全回复会安排到静默结束后，再增加 30～300 秒等待；
- 明确拒绝的礼貌结束也会等到静默结束后处理；
- 到期前如果 HR 又发来新消息，旧草稿会被取消，并按最新消息重新判断。

### 7.4 HR 常用问答

“HR 常用问答”与简历要点共同构成回复依据。

使用方法：

1. 勾选你希望启用的基础问题；
2. 在输入框中填写真实、可直接发送的答案；
3. 按需添加自定义问答；
4. 点击“保存托管设置”。

示例：

| HR 问题 | 建议答案 |
| --- | --- |
| 还在看机会吗？ | 是的，我还在看合适机会。 |
| 对这个岗位感兴趣吗？ | 感兴趣，希望进一步了解岗位和团队情况。 |
| 目前在哪个城市？ | 目前在杭州。 |

不要在问答中预先写入虚构经历、无法兑现的承诺或未经确认的薪资和到岗时间。

### 7.5 保存托管设置

修改以下任一内容后，都要点击“保存托管设置”：

- 飞书通知配置；
- 全局开关；
- 检查间隔；
- 每日自动回复上限；
- 静默时段；
- HR 常用问答。

输入框内容不是边输入边自动保存。

### 7.6 登记当前 BOSS 会话

如果岗位没有通过“联系已选”自动登记：

1. 打开 BOSS 聊天页；
2. 在左侧点开目标 HR，使中间聊天区显示正确公司、岗位和联系人；
3. 回到侧边栏“配置 → AI 托管”；
4. 决定是否勾选“登记后立即托管此岗位”；
5. 点击“从当前 Boss 聊天页登记”；
6. 确认“已登记岗位（N）”增加且出现正确卡片。

如果提示目标会话无法确认，不要反复刷新。先核对当前聊天区是否已完整加载、公司/岗位/HR 是否明确，再重试一次。

### 7.7 单个岗位托管

已登记岗位卡片提供：

- “托管此岗位”开关；
- “打开会话”；
- “重试托管”或其他状态相关操作；
- “从列表移除”。

全局开关与单个岗位开关必须同时开启。

### 7.8 批量托管

- “一键托管全部可用岗位”：开启所有当前安全可用的登记；
- “一键结束全部托管”：结束所有可结束的托管。

批量开启会跳过：

- 已结束－未匹配；
- 正在核验发送；
- 已有待确认；
- 已暂停；
- 正在等待延迟发送。

尤其不会重新开启已经明确拒绝的 HR 会话。

### 7.9 立即检查已登记岗位

点击“立即检查已登记岗位”会手动触发一次与定时任务相同的检查。

前提是：

- 全局托管已经开启并保存；
- 托管没有因前置条件变化而暂停；
- 至少有一个可检查的岗位。

结果中的常见字段：

| 字段 | 含义 |
| --- | --- |
| 检查 N 个 | 本轮成功读取的会话数 |
| 新消息 N 条 | 基线之后首次识别的新 HR 消息数 |
| 待确认 N 条 | 本轮新建的人工确认任务数 |
| 自动回复 N 条 | 本轮已取得成功证据的普通自动回复数 |

“新消息 0 条”并不一定是故障，可能只是本轮没有登记基线之后的新入站消息。

### 7.10 AI 自动回复规则

当前只对有明确依据、置信度足够高的低风险内容自动回复，例如：

- 是否仍在看机会；
- 是否方便发送简历；
- 礼貌回应；
- 请对方稍等；
- 能从简历或常用问答直接回答的事实问题。

普通回复不会在检测到消息后立即发送，而是在 30～300 秒内安排一次持久化延迟。发送前会重新读取会话；如果出现更新消息，旧草稿会被取消。

### 7.11 明确拒绝

是否属于明确拒绝完全由 AI 语义分类。只有严格判断为明确拒绝时，扩展才会：

1. 生成一条不超过 45 个汉字的礼貌结束语；
2. 不争取、不追问、不补充推销经历；
3. 自动发送一次；
4. 将会话标记为“已结束－未匹配”；
5. 后续检查不再重复回复。

典型结束语：

```text
好的，感谢您的回复，祝工作顺利。
```

含糊表达或分类不确定时不会强行结束，而会进入待确认。

### 7.12 为什么看起来“没有立刻回复”

依次检查：

1. 最近一次检查时间是否已经更新；
2. 检查间隔是否尚未到；
3. 是否处于 30～300 秒回复等待；
4. 是否处于静默时段；
5. 会话是否显示“等待确认”；
6. 会话是否显示“正在核验发送 · 持续监控”；
7. 是否达到普通自动回复日限；
8. HR 消息是否属于图片、附件或未知类型；
9. 当前 BOSS 聊天页是否为活动、可见、已加载页面。

## 8. 飞书通知

### 8.1 飞书的作用

当前飞书功能只负责通知，不能在飞书中直接批准或发送 BOSS 消息。

待确认通知可以包含经过长度限制和敏感内容清理的：

- 公司、岗位和 HR；
- HR 最新正文；
- AI 拟回复；
- 当前处理状态。

最终确认仍在扩展的“待确认”页完成。

### 8.2 配置步骤

1. 在飞书群中创建自定义机器人；
2. 复制 Webhook 地址；
3. 如机器人启用了签名校验，复制签名密钥；
4. 打开“配置 → AI 托管”；
5. 勾选“启用飞书待确认通知”；
6. 填写 Webhook 和可选签名密钥；
7. 点击“发送飞书测试通知”；
8. 确认飞书群收到测试消息；
9. 点击“保存托管设置”。

### 8.3 为什么重新打开后看不到原链接

Webhook 和签名密钥会保存在当前浏览器的 `chrome.storage.local` 中，但界面不会把原始敏感值重新显示出来。

重新打开侧边栏后，输入框可能显示：

```text
已保存；重新输入可替换
```

这表示已经保存，不是数据丢失。只有以下情况需要重新填写：

- 更换 Webhook；
- 更换签名密钥；
- 更换浏览器或浏览器资料；
- 卸载并重新安装扩展；
- 清除了扩展本地数据。

修改飞书配置后要重新发送测试通知，并再次点击“保存托管设置”。

## 9. 待确认消息

### 9.1 哪些情况会进入待确认

常见情况包括：

- 薪资、期望薪资或当前薪资；
- 面试安排；
- 到岗时间；
- 离职原因；
- 电话、微信等联系方式；
- 需要补充经验、项目或公司事实；
- 测评、Offer、承诺；
- 简历或附件操作；
- AI 置信度不足；
- 没有可引用的简历或问答依据；
- 消息类型无法安全识别；
- 含糊拒绝或其他不在低风险范围内的问题；
- 普通自动回复达到每日上限。

### 9.2 处理普通待确认

在“待确认”页：

1. 核对公司、岗位和 HR；
2. 阅读 HR 正文与上下文；
3. 修改建议回复；
4. 选择“修改并确认发送”，或“不回复并移除”；
5. 如不希望继续监控，可选择关闭该会话托管。

确认发送前，扩展还会重新打开并验证目标会话。

### 9.3 发送结果未知

如果页面已经尝试发送，但暂时没有可靠证据，扩展会显示：

“发送结果未知：请先打开 Boss 会话人工核对，系统不会重试。”

此时：

1. 点击“打开 Boss 会话”；
2. 人工确认消息是否已经出现；
3. 点击“已核对，清除此项”。

清除只删除插件本地待确认记录，不删除 BOSS 消息，也不会重新发送同一条内容。后台仍会尽可能通过只读检查寻找发送证据。

## 10. 真实外发演练

“配置 → AI 托管 → 真实外发演练”用于分段测试：

`合成 HR 消息 → 真实 AI 与策略 → 本地待确认 → 飞书通知 → 插件确认 → BOSS 发送`

### 操作步骤

1. 选择一个状态可用的已托管会话；
2. 输入一条模拟 HR 消息；
3. 勾选真实外发确认；
4. 点击“创建真实发送待确认”；
5. 查看 AI 分类、策略动作、拟回复和飞书结果；
6. 进入“待确认”；
7. 再次核对目标与回复；
8. 手动确认后，消息才可能真实发给所选 HR。

### 演练能证明什么

它可以验证：

- API 和提示词能否工作；
- 策略会自动回复、结束还是要求确认；
- 待确认能否创建；
- 飞书是否收到通知；
- 人工确认发送链路能否工作。

### 演练不能证明什么

演练使用的是合成 HR 消息，不能证明定时监控已经捕获真实新消息。

真实监控验收需要：

1. 先登记会话基线；
2. 让 HR 在基线之后新发一条消息；
3. 运行或等待下一轮检查；
4. 看到 `检查 > 0` 且 `新消息 > 0`；
5. 只出现一次预期动作；
6. 再次检查时 `新消息 = 0`，且没有重复回复。

## 11. 状态说明

| 界面状态 | 含义 | 建议操作 |
| --- | --- | --- |
| 等待 HR | 已启用，当前没有待处理新消息 | 保持浏览器和登录有效 |
| 等待回复时间 | 已生成安全草稿，等待 30～300 秒发送时刻 | 等待；有新消息会重新判断 |
| 等待静默结束后礼貌回复 | 明确拒绝发生在静默时段 | 等待静默结束 |
| 等待确认 | 需要你处理重要或不确定问题 | 前往“待确认” |
| 正在核验发送 · 持续监控 | 发送可能已经发生，正在只读寻找证据 | 不要重复发送；可打开会话核对 |
| 上次检查失败，第 N/3 次 | 瞬时读取问题，下一轮会自动重试 | 保持页面和网络可用 |
| 已暂停 | 连续失败或出现不能自动恢复的问题 | 查看原因，必要时点击“重试托管” |
| 已结束－未匹配 | AI 已处理明确拒绝并结束会话 | 不会自动重新开启 |
| 会话暂不可用 | 当前无法可靠读取或打开目标会话 | 核对登录、页面和登记身份 |

## 12. 常见问题与故障排查

### 12.1 点击“立即检查”显示检查 0 个

检查：

- 是否开启全局 AI 托管并点击“保存托管设置”；
- 单个岗位是否勾选“托管此岗位”；
- 岗位是否处于已结束、等待确认、已暂停或核验发送状态；
- 前置条件是否仍有效；
- BOSS 是否登录；
- 是否真的存在“已登记岗位”卡片。

### 12.2 已登记岗位显示未知公司或未知岗位

先点击“打开会话”。如果扩展能唯一匹配到正确会话，会尝试用当前可靠身份更新旧记录。

如果无法打开：

1. 在 BOSS 左侧手动点开目标 HR；
2. 确认聊天区公司、岗位和 HR 正确；
3. 点击“从当前 Boss 聊天页登记”；
4. 核对新卡片。

不要仅依赖地址栏中的 `uid` 判断当前会话，BOSS 单页应用切换聊天后地址栏可能保留旧值。

### 12.3 “打开会话”没有进入目标聊天

可能原因：

- 公司、岗位或 HR 信息不足；
- 列表中存在多个相似候选；
- 旧登记缺少可靠会话标识；
- BOSS 页面尚未加载完成；
- 页面结构发生变化。

扩展不会在目标不唯一时随便选择第一条。请手动打开目标 HR 后重新登记。

### 12.4 有 HR 新消息，但没有自动回复

先不要判断为故障，按顺序检查：

1. 新消息是否发生在登记基线之后；
2. 最近检查时间是否晚于 HR 消息；
3. 是否正在等待下一次 5/10/15 分钟轮询；
4. 是否正在等待 30～300 秒发送时间；
5. 是否在静默时段；
6. 是否进入“待确认”；
7. 是否达到日限；
8. 是否缺少事实依据；
9. 是否是图片、附件或未知消息；
10. 当前可见 BOSS 聊天页是否满足发送条件。

需要精确验证时，点击一次“立即检查已登记岗位”，记录结果中的检查数、新消息数和错误提示。不要连续快速点击。

### 12.5 点击重试后又暂停

只有页面脚本未就绪、会话暂不可用等瞬时读取问题可以有界重试。连续三次仍失败会暂停。

目标不确定、消息顺序不确定、登录失效、平台阻止、恢复状态不确定等问题需要人工处理，不应通过无限重试掩盖。

### 12.6 飞书配置刷新后看似消失

先看输入框是否显示“已保存；重新输入可替换”。如果有，说明配置仍在本地。

如果没有：

- 确认之前是否点击“保存托管设置”；
- 确认是否换了浏览器资料；
- 确认扩展是否被卸载重装；
- 重新填写、测试并保存。

### 12.7 API 测试以前成功，现在不能托管

修改服务商、API Key 或 Base URL 后，旧测试证明会失效。重新执行：

1. “测试连接”；
2. “保存 API 配置”；
3. 回到 AI 托管；
4. “保存托管设置”。

### 12.8 扫描到了岗位，但“联系已选”不可用

确认至少勾选了一个岗位。切换平台、重新扫描或清空选择都会取消原勾选。

### 12.9 扫描 40 个岗位，却只有少量“建议”

先区分筛选结果：

- “待核对 / 职位描述读取失败”不是岗位不匹配，可以打开站点详情人工复核后再勾选；
- 只有明确显示规则不匹配或 AI 不匹配的岗位才属于真正排除；
- 如果多数岗位同时出现“职位描述读取失败”，先重新加载扩展后再扫描一次，不要连续快速点击扫描。

BOSS 可能对连续并发打开详情返回 HTTP 200 的“请稍候”软加载页。当前版本改为在已有搜索页中逐个激活岗位并核对稳定 ID；单次扫描因此更慢，但不会再把软加载页当成真实职位描述。只有页面明确出现验证码、登录失效、操作频繁或账号异常提示时，才按平台验证处理；仅凭“建议数量少”不能判断账号被风控。

### 12.10 所有岗位都报“目标职位详情缺少可核验的 HR 身份”

这条错误发生在真正点击“立即沟通”之前，表示扩展已经锁定岗位，但没有从同一详情面板取得唯一招聘者姓名。若同一批岗位 100% 都报错，通常是扩展版本过旧或招聘网站详情 DOM 已变化，不等于账号被风控。

处理顺序：

1. 停止连续重试；
2. 在扩展管理页重新加载最新版本；
3. 重新打开 BOSS 搜索页并扫描；
4. 若仍然全部失败，保存“执行”页完整日志用于适配器排查。

当前实现只接受已核验详情面板中的唯一 HR；不会用列表卡片字段猜测，也不会在两个 HR 候选冲突时联系。

### 12.11 显示“已向BOSS发送消息”，但日志说未进入聊天页或没有 AI 托管

这通常不是 BOSS 风控。该弹窗已经说明 BOSS 已发出首条招呼，“继续沟通”只负责进入聊天页；只有进入聊天页并只读取得唯一会话身份后，扩展才能登记 AI 托管。

当前版本会保留该成功回执，不会用通用关闭规则点掉弹窗，并只点击本次联系产生的唯一“继续沟通”。两个岗位筛选入口都使用这条公共链路：

- “联系已选”进入聊天页后登记会话，但保持未托管；
- “联系已选并开启 AI 托管”进入聊天页后登记并启用托管。

这两个入口都不会在成功回执之后再次发送招呼。好友列表缺少岗位字段也不等于身份冲突：扩展会以严格核验过的聊天页岗位补全登记，同时要求好友列表已有的 HR 与公司证据一致。

如果更新后仍停在岗位页：

1. 先检查 BOSS 会话列表，确认首条招呼是否已经出现；
2. 不要再次点击同一岗位，避免重复联系；
3. 重新加载扩展，再重新打开 BOSS 搜索页；
4. 保存从“发起沟通”开始的完整日志，并确认是否出现“发送结果未知”或“AI 托管未登记”。

孤立的“成功”返回但页面仍在岗位列表时，扩展不会再计为完整成功，也不会显示托管已开启。若首条招呼已经出现、但只读会话捕获失败，扩展会保留“联系成功”结果并明确提示“会话登记失败”，不会重放招呼或把整个联系批次误停机。

扩展内部出现“没有消息接收端”或“扩展上下文已失效”时，也不会把该错误当成已进入聊天页；请重新加载扩展和 BOSS 页面后再操作。一般消息通道关闭只有在随后确认 URL 已进入聊天页时才会继续登记。

### 12.12 页面出现验证码或登录失效

停止当前自动操作，在招聘网站中人工完成登录或验证。确认页面恢复正常后，再重新扫描或恢复托管。

## 13. 数据、隐私与安全

### 13.1 本地保存内容

扩展会在当前浏览器的扩展本地存储中保存必要配置和状态，例如：

- API Key；
- 飞书 Webhook 与签名密钥；
- 求职设置；
- 简历要点和问答；
- 已登记岗位；
- 待确认任务；
- 联系计数和执行检查点。

当前版本没有接入操作系统钥匙串。

### 13.2 AI 与外部服务

使用 AI 功能时，完成判断所需的有限岗位、简历或聊天内容会发送到你配置的模型服务。使用飞书通知时，经过限制和清理的通知内容会发送到你配置的飞书机器人。

不要在简历要点、问答或通知中保存不必要的密码、验证码、支付信息或高敏感个人信息。

### 13.3 安全原则

- 不确定目标时不发送；
- 同一发送结果未知时不自动重放；
- 验证码或平台异常时停止；
- 明确拒绝只礼貌结束一次；
- 已结束－未匹配不会被批量托管重新开启；
- 重要问题必须人工确认；
- 自动化不能替代你对岗位和回复内容的最终判断。

## 14. 更新、重载与卸载

### 14.1 更新扩展

更新项目文件后，在扩展管理页点击“重新加载”。建议随后：

1. 打开侧边栏；
2. 确认版本和主要标签正常；
3. 测试 API；
4. 测试飞书；
5. 用少量岗位跑一次扫描；
6. 再恢复较大批次或 AI 托管。

### 14.2 卸载前

卸载扩展通常会清除其本地存储。卸载前请自行保存：

- API 和飞书服务的来源信息；
- 需要保留的求职设置；
- 尚未处理的待确认内容；
- 需要人工继续跟进的会话。

### 14.3 获取故障信息

反馈问题时，建议提供：

- 浏览器名称和版本；
- 扩展版本；
- 当前平台；
- 操作步骤；
- 侧边栏状态文字；
- “执行”页日志；
- 可隐藏个人信息后的截图；
- 问题发生时间。

不要公开 API Key、飞书 Webhook、签名密钥、登录 Cookie 或完整私人聊天记录。
