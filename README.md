# 求职联系助手

半自动 Chrome/Edge 侧边栏扩展：在招聘站点 **扫描 → 人工勾选 → 仅对已选岗位逐个发起沟通**。

- 已支持：**Boss 直聘、智联招聘**
- 适配中：**猎聘**（配置页可选，但扫描保持禁用）

基于 [JobCopilot](https://github.com/huluobo2237-pixel/JobCopilot)（MIT）改造。产品红线：默认全不选；多人批次只确认一次，但后台必须逐岗校验；遇验证码、日限或不确定结果立即停机。

## 安装

1. `chrome://extensions` → 开发者模式  
2. 「加载已解压的扩展程序」→ 选本仓库根目录  
3. 登录对应招聘网站 → 打开侧边栏

## 使用

1. **配置 → 平台**：选择 Boss / 智联 / 猎聘（同时只跑一个）  
2. **API Key**：BYOK，全平台共用（DeepSeek 使用 `deepseek-v4-flash`；旧名 `deepseek-chat` 已下线）  
3. **求职设置**：意向（关键词/城市）、简历材料、平台条件、招呼语、扫描与联系节奏（**每平台独立**）→ 扫描  
4. **岗位筛选**：勾选一个或多个岗位 →「联系已选」
5. **批次确认**：一次查看平台、岗位清单、排除项、今日额度、预计等待和简历状态  
6. **执行**：确认一次后系统逐岗校验；可查看日志、暂停或停止  

取消、按 Escape 或点击确认单遮罩均会返回岗位筛选，不会启动招聘网站操作。确认单有效期为两分钟且只能消费一次；失效后需重新确认。

智联城市会转换为现行数字城市 ID，并在扫描后按职位卡地点再次校验；工作经验和学历也会按职位卡字段精确过滤。城市留空时按全国搜索；当前可识别：全国、北京、天津、上海、重庆、南京、杭州、厦门、武汉、广州、深圳、成都、西安。无法识别的城市会停止扫描，不会静默退化成全国结果。

## Boss AI 对话托管（Phase 1）

托管只适用于插件已经成功联系、且用户逐会话明确开启的 Boss 会话。智联和猎聘尚未启用这条链路。全局开关和每个会话开关都默认关闭；关闭全局开关时不会保留监控 alarm 或访问页面。

登录与平台适配继续参考 [boss-agent-cli](https://github.com/can4hou6joeng4/boss-agent-cli) 的用户主动登录、Cookie/CDP/二维码分级回退、平台接口隔离和默认阻断高风险写操作等设计。当前扩展只复用用户已经打开的 Chrome 登录态，不导出或自行持久化 Boss Cookie，也不把登录链路用于规避平台风控；登录失效、验证码或页面阻止会暂停托管并等待用户处理。

启用前必须完成同版本 API 连通性测试、填写简历依据、完成飞书测试并接受风险提示。检查间隔只能选择 5 / 10 / 15 分钟，默认 10 分钟；普通自动回复日限默认为 10、可配置范围为 1–20；也可设置静默时段。只有有明确简历或配置依据的低风险白名单问题才可能自动回复；通过策略门后不会立即发送，而是持久化一个 30–300 秒的随机回复时刻，到点后重新读取目标会话，发现更新来信就取消旧草稿并按最新消息重新决策。静默时段中的普通安全回复会排到静默结束后再叠加该随机延迟。薪资、面试、到岗、离职原因、联系方式、经历补充、测评、Offer、承诺、附件和未知类型始终进入插件内人工确认。明确拒绝完全由 AI 语义分类；只有严格 `explicit_rejection` 才会生成并安全校验一条 45 字内礼貌结束语，非静默时单次发送后标记“已结束－未匹配”。静默时段先冻结为“等待静默结束后礼貌回复”，退出静默后重读无新消息才发送；有更新来信会取消旧结束动作。该结束动作不计入普通日限，也不会重复回复。

“已登记岗位（N）”中的数字是本地持久化登记的事实状态；登记按钮上方的成功或失败提示只说明最近一次操作结果。只有数量增加并出现岗位卡片，才表示该岗位确实登记成功。

Boss 登记基线、周期增量和发送后证据从当前登录页面的同源历史接口读取。登记时同时保存好友列表中的 canonical `encryptUid` 和对端数字 `uid`；每条历史消息按 `from.uid / to.uid` 与该对端数字 UID 的关系判定 incoming/outgoing，`received` 只保留为诊断字段，不能作为方向事实。游标优先取消息 ID 并在缺失时回退到消息时间；历史响应不再假设固定倒序，而是优先按可靠消息时间升序、同时间按数字消息 ID 升序归一化，避免真实接口按旧到新返回时漏掉 baseline 后的新来信。BOSS 自带的已读、附件/简历通知、竞争分析等无方向卡片不会再阻断登记。接口新增的未知消息类型会降级为“非文本消息”交人工确认，而不是让整批读取失败。BOSS 单页聊天切换后地址栏可能保留上一位 HR 的旧 `uid`；手动登记会把页面 `uid`、最新同源 `historyMsg bossId` 和活动会话 scoped identity 一起与好友列表核对，只有唯一一致的 peer 才能登记，不能再用旧 URL 覆盖当前可见会话。一键联系后的自动登记同样以聊天页好友列表解析出的公司、岗位、联系人和 `peerUid` 为准，岗位筛选卡片字段只在结构化字段缺失时补位；空字段不得覆盖已有身份。旧版产生的“未知公司/联系人错位”记录，在用户点击“打开会话”且规范 ID 唯一解析成功后会回写修复。发送时仍严格确认活动会话身份；后续只读周期直接使用 store 中已经验证并严格净化的稳定 ID 读取历史，不会为检查而切换会话。旧登记若尚未保存数字 UID，会先用 canonical peer 从好友列表唯一补齐；补齐失败即停止读取。

后台只读检查会优先复用你已经打开的 Boss 聊天标签：只在其中发一次同源历史消息请求，不刷新、不导航、不切换会话、不改动页面，也不会在检查结束后关掉这个标签；没有可复用标签时才新建一个独占、不可见的临时标签，用完即关。Boss 现网页面不能假定 `?uid=` 会自动激活目标会话，因此只读路径不模拟点击，只对持久化稳定引用重新做格式/域名净化后请求历史消息。侧栏“打开会话”属于用户显式导航动作：优先复用当前焦点窗口的 Boss 聊天页，按公司/岗位/HR 点击唯一候选，再以 canonical peerId/alias 和 scoped identity 复核；只有复核成功才显示打开成功，不能再把新建 `?uid=` 标签等同于已进入目标会话。真正发送只允许使用当前焦点窗口中处于 active、加载完成的 Boss 聊天页，在同一可见页激活唯一目标并再次核对身份、冻结发送意图和发送后新 outgoing 证据。消息列表、编辑器和发送按钮在现网是同一 `.chat-conversation` 下的不同分支；发送器从消息容器向上寻找包含唯一可见输入框和发送按钮的最近共同会话祖先，不能把消息容器的直接父级误当作控件作用域，也不能退化为全页面查找。后台不可见临时标签只承担只读回退，不再承担写入。发送时没有符合条件的活动 Boss 聊天页会收束为结果未知并停止重试。

API 连接证明与运行时配置使用同一个原子配置快照：`PlatformConfig.loadFlat()` 会保留 `apiConfigVersion / apiLastTestVersion / apiLastTestOk / apiLastTestAt`，避免侧栏前置检查已经通过、真正读取时却因证明字段被投影丢失而误报“会话暂不可用”。若 API 凭证或证明在读取途中确实变化，监控会以全局 `PREREQUISITE_CHANGED` 暂停，不再累计到某个岗位的读取失败次数。

只读检查遇到“页面脚本未就绪／会话暂不可用／页面结构暂不可用”这类无外部写入的瞬时问题时不会立刻暂停，而是保留在监控中并在下一轮自动重试，岗位卡显示“上次检查失败（原因），第 N/3 次，下轮自动重试”；连续 3 次仍失败才转为“已暂停”，此时点“重试托管”可无损恢复，消息游标不会被清空。任一次检查成功都会清零重试计数。消息结构变化会显示明确的 `MESSAGE_ORDER_UNCERTAIN` 中文说明并停止自动回复，目标不确定和恢复状态不确定仍失败关闭。发送动作已经发生但回执暂未出现时不会重发，也不会关闭整个会话：发送器先有界等待历史回执，仍未知则进入 `VERIFYING_SEND`，后续周期只读查找同一目标、同一草稿且晚于意图创建时间的唯一 outgoing 证据；确认后恢复 `WAITING_HR` 并继续多轮监控。

“立即检查已登记岗位”只有在全局托管已开启且未暂停时才会进入监控引擎。全局关闭或暂停时会明确提示“请先开启 AI 对话托管并保存设置”，不会再把没有读取任何岗位的空跑显示成“检查 0 个，已完成”。连续周期以持久化消息 ID 为游标：同一条新入站消息只进入一次分类/待确认链，后续周期不得重复处理。

待确认飞书通知可以包含经过长度限制和敏感信息清洗的 HR 最新正文与拟回复，同时附带稳定状态和公司/岗位/HR 元数据；飞书仍只负责通知，不能直接批准或发送。签名和请求序列化完成后，runtime 会再次读取最新持久状态；background 保护层会先复核 API proof，再把同一份最新快照交给 engine 的 owner/link/唯一待办断言，两个证明都通过后才在同一同步调用栈发起真实 fetch。插件内待确认工作台可以查看本地有界上下文、修改草稿并发送；普通待办可选“不回复并移除”。若一次发送已进入 `SEND_RESULT_UNKNOWN`，卡片只允许“打开 Boss 会话”人工核对和“已核对，清除此项”，后台则保持 `VERIFYING_SEND` 只读核验；清除只删除插件本地待确认记录，不删除 Boss 消息，也不会让终态 intent 重新可发送。关闭托管会话会删除其最近上下文和活动待办。API Key、飞书 Webhook 和签名密钥只保存在 `chrome.storage.local`，当前版本没有接入操作系统钥匙串。

「配置 → AI 托管 → 真实外发演练」允许选择一个处于“等待 HR”的已托管会话，输入一条合成 HR 消息，并在每次操作前勾选真实外发确认。演练使用真实 AI、简历/问答依据和确定性策略；它会如实显示 `AUTO_REPLY`、`AUTO_CLOSE` 或 `REQUIRE_CONFIRMATION`，但无论评估结果如何都只写入生产待确认队列并尝试发送飞书通知，不会在演练入口创建自动发送意图。只有用户随后在插件「待确认」页核对目标与草稿并执行发送，才会重新读取并验证目标会话后真实发给所选 HR。合成输入不会修改真实监控 baseline、已处理指纹、最近真实消息、监控游标或自动回复额度。

真实外发演练只能验证“合成输入 → AI/策略 → 本地待确认 → 飞书 → 插件确认 → Boss 发送”链路，不能证明插件已经捕获真实 HR 新消息。真实监控验收必须在登记 baseline 之后由 HR 新发一条消息，并看到同一周期 `checked > 0`、`newMessages > 0`，随后只产生一次预期动作；再次检查应为 `newMessages = 0` 且不得重复回复。

Chrome 必须保持运行且 Boss 登录有效。登录失效、验证码/风控、目标不确定或关键页面结构不可确认会失败关闭；发送结果未知绝不自动重放，但会保持只读核验而不是永久退出托管。2026-07-26 已用 ego-browser 复用真实登录态确认：10 分钟同名 alarm 存在；两个已登记 canonical peer 能在不刷新、不切换页面的情况下完成受保护历史读取；“打开会话”能在当前窗口内正反切换并以切换后的可见标题、公司/HR scoped identity 和 exact canonical peer/alias 复核。真实外发演练首次在不可见临时页没有产生 Boss 消息；随后经用户授权，在可见活动 Boss 页对精确目标和草稿单次重试，15:44 出现新的 `[送达]` outgoing 气泡。实号历史同时证明当前接口对双方消息都返回 `received=true`，原实现据此误判方向并把已发送证据识别成 incoming；现已改为数字对端 UID + `from/to` 判向。之后对徐海霞会话的单次发送排查确认：目标绑定和历史读取均成功，但真实 DOM 的消息区直接父级 `.message-content` 不包含位于兄弟分支的输入框/发送按钮，旧代码在任何输入或按键前即失败；现已改为有界解析最近共同会话祖先并保持唯一控件门禁。该证据证明一次人工确认发送路径已经真实成功，但这次失败项没有实际外发；真实 HR 新来信后的定时捕获、LLM 分类/草稿/自动回复和真实飞书通知仍需独立验收。使用自动化功能可能违反平台条款或触发账号限制，请仅在理解风险并获授权的账号与岗位上分阶段验证。完整边界见 `docs/08-boss-ai-trusteeship.md`。

若扩展升级或后台中断后发现任何仍为 `SENDING` 的意图，会先收束为 `SEND_RESULT_UNKNOWN / VERIFYING_SEND`，AUTO 额度只消费一次且绝不重放；后续只读核验发现唯一发送证据才恢复 `WAITING_HR`。分类证据不能遮蔽未知发送。只有不存在未知发送时，系统才检查分类前游标、活动消息、原状态及唯一待办；证据不足会以 `RECOVERY_STATE_UNCERTAIN` 暂停。矛盾、孤儿或重复待办不会触发飞书通知。损坏的未知暂停码会统一显示为 `UNKNOWN_PROCESSING_FAILURE`，任意原始 `pauseReason` 会被清空。公共 settings 响应按固定字段逐项重建，不会把新增的内部存储字段自动带到面板。未知发送仍可由用户在 Boss 人工核对；待确认卡的“已核对，清除此项”只清理插件本地记录，原发送意图保持不可重放。

已登记岗位支持“一键托管全部可用岗位”和“一键结束全部托管”。批量操作在 store 内一次原子完成，不由侧栏逐卡循环；`ENDED_UNMATCHED`、发送核验中、待确认、暂停或延迟中的会话会被跳过，尤其不会重新联系已经明确拒绝的 HR。岗位筛选页“联系已选”成功登记后，侧栏监听持久存储变化并重新读取 runtime 公共状态，已登记列表会自动更新；刷新只重绘动态状态，不覆盖用户尚未保存的托管表单。

## 运行安全

- 发送前必须匹配当前会话的岗位、公司或 HR；无法确认目标时不发送简历或招呼语。
- 后台只接受 `PREPARE_DELIVERY → CONFIRM_DELIVERY` 流程；旧的直接联系入口会返回 `CONFIRMATION_REQUIRED`，不能绕过确认。
- 确认时冻结本批次岗位 ID，并重新检查当前平台、扫描缓存、已联系记录和今日剩余额度。多人批次不要求逐人确认。
- 回车与发送按钮是互斥的两级提交，不会对同一条招呼语连续执行两次发送动作。
- 建联成功或结果不确定时立即写入去重与今日计数；招呼语失败不会自动重试联系，发送结果未知会停止整个批次。
- 运行中锁定平台并禁用会话重置；停止会取消等待和网络请求，并在下一次外部动作前生效。
- 任务检查点保存在 `chrome.storage.local`。若 MV3 后台意外中断，任务进入停机态，必须人工核对后重新扫描。
- 停机卡片会显示稳定错误代码、原因和下一步操作；只有未发生外部写入的只读失败允许有界自动重试（3 次）和人工点击“重试托管”，目标不确定、发送结果未知和后台中断不会自动恢复或重放。
- 自定义 OpenAI 兼容 Base URL 会按域名请求权限；公网仅允许 HTTPS，本机 `localhost` / `127.0.0.1` 可使用 HTTP。

## 开发验证

需要 Node.js 18 或更高版本：

```bash
npm test
for f in $(rg --files -g '*.js'); do node --check "$f"; done
python3 -m json.tool manifest.json >/dev/null
```

自动化套件覆盖批次计划、两分钟一次性意图、并发双消费、后台强制确认、确认弹窗与键盘语义、结构化停机、单次发送、目标会话匹配、Boss 历史接口消息方向/未知类型降级/稳定游标与时间回退、只读标签复用与临时标签回退、只读失败有界退避、JavaScript URL 安全点击、取消与平台隔离、原子联系记账、持久运行恢复、自定义 API 权限、Boss 托管恢复/静默/alarm/隐私契约，以及智联城市/经验/学历筛选。

真实招聘网站 DOM、登录态、弹窗和账号风控不能由 Node 单测证明。Boss 与智联的测试账号真机联系均为 **待验收**；在用户明确授权测试账号和测试岗位前，不执行真实投递或发送，也不宣称真实平台验证通过。
