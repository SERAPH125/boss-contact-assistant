# 求职联系助手

半自动 Chrome/Edge 侧边栏扩展：在招聘站点 **扫描 → 人工勾选 → 仅对已选岗位逐个发起沟通**。

- 已支持：**Boss 直聘、智联招聘**
- 适配中：**猎聘**（配置页可选，但扫描保持禁用）

基于 [JobCopilot](https://github.com/huluobo2237-pixel/JobCopilot)（MIT）改造。产品红线：默认全不选；多人批次只确认一次，但后台必须逐岗校验；遇验证码、日限或不确定结果立即停机。

## 安装

1. `chrome://extensions` → 开发者模式  
2. 「加载已解压的扩展程序」→ 选本仓库根目录  
3. 登录对应招聘网站 → 打开侧边栏

## 使用

1. **配置 → 平台**：选择 Boss / 智联 / 猎聘（同时只跑一个）  
2. **API Key**：BYOK，全平台共用（DeepSeek 使用 `deepseek-v4-flash`；旧名 `deepseek-chat` 已下线）  
3. **求职设置**：意向（关键词/城市）、简历材料、平台条件、招呼语、扫描与联系节奏（**每平台独立**）→ 扫描  
4. **审核**：勾选一个或多个岗位 →「联系已选」  
5. **批次确认**：一次查看平台、岗位清单、排除项、今日额度、预计等待和简历状态  
6. **执行**：确认一次后系统逐岗校验；可查看日志、暂停或停止  

取消、按 Escape 或点击确认单遮罩均会返回审核，不会启动招聘网站操作。确认单有效期为两分钟且只能消费一次；失效后需重新确认。

智联城市会转换为现行数字城市 ID，并在扫描后按职位卡地点再次校验；工作经验和学历也会按职位卡字段精确过滤。城市留空时按全国搜索；当前可识别：全国、北京、天津、上海、重庆、南京、杭州、厦门、武汉、广州、深圳、成都、西安。无法识别的城市会停止扫描，不会静默退化成全国结果。

## Boss AI 对话托管（Phase 1）

托管只适用于插件已经成功联系、且用户逐会话明确开启的 Boss 会话。智联和猎聘尚未启用这条链路。全局开关和每个会话开关都默认关闭；关闭全局开关时不会保留监控 alarm 或访问页面。

登录与平台适配继续参考 [boss-agent-cli](https://github.com/can4hou6joeng4/boss-agent-cli) 的用户主动登录、Cookie/CDP/二维码分级回退、平台接口隔离和默认阻断高风险写操作等设计。当前扩展只复用用户已经打开的 Chrome 登录态，不导出或自行持久化 Boss Cookie，也不把登录链路用于规避平台风控；登录失效、验证码或页面阻止会暂停托管并等待用户处理。

启用前必须完成同版本 API 连通性测试、填写简历依据、完成飞书测试并接受风险提示。检查间隔只能选择 5 / 10 / 15 分钟，默认 10 分钟；自动回复日限默认为 10、可配置范围为 1–20；也可设置静默时段。只有有明确简历或配置依据的低风险白名单问题才可能自动回复，薪资、面试、到岗、离职原因、联系方式、经历补充、测评、Offer、承诺、附件和未知类型始终进入插件内人工确认。

“已登记岗位（N）”中的数字是本地持久化登记的事实状态；登记按钮上方的成功或失败提示只说明最近一次操作结果。只有数量增加并出现岗位卡片，才表示该岗位确实登记成功。

Boss 登记基线、周期增量和发送后证据从当前登录页面的同源历史接口读取，方向取接口的收发标记，游标优先取消息 ID 并在缺失时回退到消息时间；BOSS 自带的已读、附件/简历通知、竞争分析等无方向卡片不会再阻断登记。接口新增的未知消息类型会降级为“非文本消息”交人工确认，而不是让整批读取失败。BOSS 单页聊天切换后地址栏可能保留上一位 HR 的旧 `uid`；手动登记会把页面 `uid`、最新同源 `historyMsg bossId` 和活动会话 scoped identity 一起与好友列表核对，只有唯一一致的 peer 才能登记，不能再用旧 URL 覆盖当前可见会话。登记时用好友列表唯一建立 canonical peerId/alias，发送时仍严格确认活动会话身份；后续只读周期直接使用 store 中已经验证并严格净化的稳定 ID 读取历史，不再重复依赖好友列表或当前活动 DOM，也不会为检查而切换会话。

后台只读检查会优先复用你已经打开的 Boss 聊天标签：只在其中发一次同源历史消息请求，不刷新、不导航、不切换会话、不改动页面，也不会在检查结束后关掉这个标签；没有可复用标签时才新建一个独占、不可见的临时标签，用完即关。Boss 现网页面不能假定 `?uid=` 会自动激活目标会话，因此只读路径不模拟点击，也不在每轮重新请求易漂移的好友列表，只对持久化稳定引用重新做格式/域名净化后请求历史消息。侧栏“打开会话”属于用户显式导航动作：优先复用当前焦点窗口的 Boss 聊天页，按公司/岗位/HR 点击唯一候选，再以 canonical peerId/alias 和 scoped identity 复核；只有复核成功才显示打开成功，不能再把新建 `?uid=` 标签等同于已进入目标会话。只有真正发送时才会在独占临时标签的会话列表中按公司、岗位、HR 唯一匹配并激活，随后再用 canonical peerId/alias、scoped identity、冻结发送意图和发送后新 outgoing 证据复核。

API 连接证明与运行时配置使用同一个原子配置快照：`PlatformConfig.loadFlat()` 会保留 `apiConfigVersion / apiLastTestVersion / apiLastTestOk / apiLastTestAt`，避免侧栏前置检查已经通过、真正读取时却因证明字段被投影丢失而误报“会话暂不可用”。若 API 凭证或证明在读取途中确实变化，监控会以全局 `PREREQUISITE_CHANGED` 暂停，不再累计到某个岗位的读取失败次数。

只读检查遇到“页面脚本未就绪／会话暂不可用／页面结构暂不可用”这类无外部写入的瞬时问题时不会立刻暂停，而是保留在监控中并在下一轮自动重试，岗位卡显示“上次检查失败（原因），第 N/3 次，下轮自动重试”；连续 3 次仍失败才转为“已暂停”，此时点“重试托管”可无损恢复，消息游标不会被清空。任一次检查成功都会清零重试计数。消息结构变化会显示明确的 `MESSAGE_ORDER_UNCERTAIN` 中文说明并停止自动回复，目标不确定、未知发送和恢复状态不确定仍一次即暂停且禁止直接重试。

“立即检查已登记岗位”只有在全局托管已开启且未暂停时才会进入监控引擎。全局关闭或暂停时会明确提示“请先开启 AI 对话托管并保存设置”，不会再把没有读取任何岗位的空跑显示成“检查 0 个，已完成”。

飞书只发送固定提示、稳定状态和公司/岗位/HR 等安全元数据，不能在飞书直接批准或发送；HR 聊天、模型草稿和待补字段均不会进入飞书载荷。签名和请求序列化完成后，runtime 会再次读取最新持久状态；background 保护层会先复核 API proof，再把同一份最新快照交给 engine 的 owner/link/唯一待办断言，两个证明都通过后才在同一同步调用栈发起真实 fetch。插件内待确认工作台可以查看本地有界上下文、修改草稿并发送；关闭托管会话会删除其最近上下文和活动待办。API Key、飞书 Webhook 和签名密钥只保存在 `chrome.storage.local`，当前版本没有接入操作系统钥匙串。

Chrome 必须保持运行且 Boss 登录有效。登录失效、验证码/风控、目标不确定、选择器失效或发送结果未知都会失败关闭；发送结果未知绝不自动重放。2026-07-26 已用 ego-browser 复用真实登录态确认：10 分钟同名 alarm 存在；两个已登记 canonical peer 都能在不刷新、不切换页面的情况下完成受保护历史读取；“打开会话”在当前窗口内对徐海霞与谭辉两条会话正反切换均返回成功，并由切换后的可见标题、公司/HR scoped identity 和 exact canonical peer/alias 共同复核。反向切换时地址栏仍保留上一条会话的旧 `uid`，最终捕获仍准确得到当前谭辉 peer，证明 URL 不再被误当作当前会话事实。真实托管发送、真实新来信后的 LLM 分类/草稿/自动回复和真实飞书通知仍未验收，不能由无新消息的只读成功或打开成功替代。使用自动化功能可能违反平台条款或触发账号限制，请仅在理解风险并获授权的账号与岗位上分阶段验证。完整边界见 `docs/08-boss-ai-trusteeship.md`。

若扩展升级或后台中断后发现任何仍为 `SENDING` 的意图，会先收束为 `SEND_RESULT_UNKNOWN`，AUTO 额度只消费一次且绝不重放；分类证据不能遮蔽未知发送。只有不存在未知发送时，系统才检查分类前游标、活动消息、原状态及唯一待办；证据不足会以 `RECOVERY_STATE_UNCERTAIN` 暂停。矛盾、孤儿或重复待办不会触发飞书通知。损坏的未知暂停码会统一显示为 `UNKNOWN_PROCESSING_FAILURE`，任意原始 `pauseReason` 会被清空；只有未知发送保留固定 `SEND_RESULT_UNKNOWN` reason。公共 settings 响应按固定字段逐项重建，不会把新增的内部存储字段自动带到面板。请先在 Boss 人工核对会话，再重新开启该岗位托管。

## 运行安全

- 发送前必须匹配当前会话的岗位、公司或 HR；无法确认目标时不发送简历或招呼语。
- 后台只接受 `PREPARE_DELIVERY → CONFIRM_DELIVERY` 流程；旧的直接联系入口会返回 `CONFIRMATION_REQUIRED`，不能绕过确认。
- 确认时冻结本批次岗位 ID，并重新检查当前平台、扫描缓存、已联系记录和今日剩余额度。多人批次不要求逐人确认。
- 回车与发送按钮是互斥的两级提交，不会对同一条招呼语连续执行两次发送动作。
- 建联成功或结果不确定时立即写入去重与今日计数；招呼语失败不会自动重试联系，发送结果未知会停止整个批次。
- 运行中锁定平台并禁用会话重置；停止会取消等待和网络请求，并在下一次外部动作前生效。
- 任务检查点保存在 `chrome.storage.local`。若 MV3 后台意外中断，任务进入停机态，必须人工核对后重新扫描。
- 停机卡片会显示稳定错误代码、原因和下一步操作；只有未发生外部写入的只读失败允许有界自动重试（3 次）和人工点击“重试托管”，目标不确定、发送结果未知和后台中断不会自动恢复或重放。
- 自定义 OpenAI 兼容 Base URL 会按域名请求权限；公网仅允许 HTTPS，本机 `localhost` / `127.0.0.1` 可使用 HTTP。

## 开发验证

需要 Node.js 18 或更高版本：

```bash
npm test
for f in $(rg --files -g '*.js'); do node --check "$f"; done
python3 -m json.tool manifest.json >/dev/null
```

自动化套件覆盖批次计划、两分钟一次性意图、并发双消费、后台强制确认、确认弹窗与键盘语义、结构化停机、单次发送、目标会话匹配、Boss 历史接口消息方向/未知类型降级/稳定游标与时间回退、只读标签复用与临时标签回退、只读失败有界退避、JavaScript URL 安全点击、取消与平台隔离、原子联系记账、持久运行恢复、自定义 API 权限、Boss 托管恢复/静默/alarm/隐私契约，以及智联城市/经验/学历筛选。

真实招聘网站 DOM、登录态、弹窗和账号风控不能由 Node 单测证明。Boss 与智联的测试账号真机联系均为 **待验收**；在用户明确授权测试账号和测试岗位前，不执行真实投递或发送，也不宣称真实平台验证通过。

## 风险声明

自动化可能违反平台用户协议，后果自负。API Key 仅存本机。详见 `docs/07-multi-platform-design.md`。
